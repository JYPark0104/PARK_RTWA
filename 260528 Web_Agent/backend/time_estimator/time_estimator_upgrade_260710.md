# 시간 예측 시스템 점검·업그레이드 (2026-07-10)

6.RT 실행 전 "얼마나 걸릴지" 예측의 편차 원인을 분석하고 보완한 기록.

## [1] 이력 분석 (run_history.jsonl, 35건)
- 전부 `intg` 엔진, 전부 **SISO(num_ant_pairs=1)**, depth 대부분 5, num_samples 100000.
- RX 1,586 ~ 100,124 / TX 1~19. RT 시간 수십 초 ~ 5.7시간.
- **동일 설정 반복인데 RT 시간이 크게 흔들림**:
  - tx18·rx7615(8회): RT 714~1562s (**2.19배**)
  - tx19·rx9950(3회): 545~3262s (**5.99배**)
  - tx8·rx33669(2회): 1669~3998s (2.40배)

## [2] 편차·분산이 큰 이유
1. **공유 GPU 경합(가장 큼)**: dclserver78 은 여러 작업(다른 venv/컨테이너, 멈춘 잡 등)이 GPU 를
   같이 쓴다. 동일 config 가 2~6배 흔들리는 건 config 로 설명 안 되는 **외부 경합**이 주원인.
   → 근본적으로 예측 불가능한 성분.
2. **미포착 피처**: RT 시간을 크게 좌우하는 PathSolver 옵션(회절/확산반사/투과)이 기록/매칭에
   없었다. 옵션이 다른 실행이 한 통에 섞여 분산을 키움.
3. **머신 키 분열(버그)**: 같은 머신인데 `gpu_name` 이 실행마다 None / "H100 NVL" 로 갈려
   machine_key 가 둘로 쪼개짐(25 vs 10건). 예측 시 한쪽(≤10건)만 매칭 → 데이터 71% 낭비.

## [3] 피처/피팅 점검
- **피처 과다**: RT basis 의 `× num_ant_pairs`(안테나쌍) 곱은 **35건 모두 ap=1** 이라 전혀
  검증되지 않음. MIMO 예측은 순수 외삽(선형 가정)이라 위험(과대 추정 가능).
- **피처 부족**: PathSolver 옵션(회절/확산/투과), synthetic_array 미기록.
- **피팅 문제**: 기존 1순위였던 **affine(d=a·x+b) 적합이 오히려 해로움**. basis 가 1.5e3~1.5e6 로
  3자릿수 이상 걸쳐 있어 절편·기울기가 과적합/외삽되어 오차를 키움.
  (leave-one-out 백테스트) affine MAPE **87.9%** vs 중앙값-rate 비례 **43.6%**.

## [4] 구현한 개선
1. **머신 매칭 안정화**: 매칭을 `machine_id + gpu_mode` 필드로 직접 수행(gpu_name 을 키에서 제외).
   `machine.py` 는 nvidia-smi 폴백으로 gpu_name 을 일관되게 채움.
   → 예측 시 매칭 표본 **10 → 33건**(같은 머신 전체 활용).
2. **피처 확장 + 매칭**: PathSolver 옵션(diffraction/diffuse_reflection/refraction/synthetic_array)을
   기록하고 매칭 와일드카드로 사용(구 레코드는 없어 자동 통과=하위호환). 앞으로 '같은 연산옵션'끼리만
   비교되어 분산이 줄어든다.
3. **피팅 교체**: affine → **단계별 중앙값 rate(비례)**. 백테스트 MAPE **87.9% → 43.6%**,
   p90 오차 218% → 122%. (고정 오버헤드는 Scene 단계 분리로 흡수)
4. **정직한 불확실성 + 신뢰도 등급**: ± 는 rate 분포 p15~p85 폭을 투영(경합 변동 반영).
   `confidence`(high/medium/low) + `warnings` 추가. 표본 부족·외삽 시 medium/low.
5. **외삽 경고**: 타깃 안테나쌍/RX 가 과거 범위를 크게 벗어나면(특히 MIMO) 신뢰도 low +
   경고 문구 + 밴드를 최소 ±50%로 확대해 과신 방지.

## 남은 한계(정직하게)
- 오차의 **상당 부분은 공유 GPU 경합**이라 config 기반 예측으로는 원천적으로 못 줄인다
  (동일 config 가 2~6배). MAPE ~40%대는 이 데이터에서 사실상 하한에 가깝다.
- MIMO(ap>1) 실측 데이터가 쌓이면 안테나쌍 스케일링을 실측으로 보정 가능(현재는 외삽·경고 처리).
- 더 낮추려면 "실행 중 GPU 점유율/동시 잡 수"를 피처로 넣거나, 전용 GPU 격리가 필요.
